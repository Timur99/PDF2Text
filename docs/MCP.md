# PDF2Text MCP

Локальный сервер для извлечения текста из PDF и изображений. MCP-клиент запускает
его через stdio; HTTP-порт, веб-приложение и запущенный DMG не нужны.

## Установка из исходников

Нужны Git и Python 3.11+. Для Apple Vision — macOS 13+.

```bash
git clone https://github.com/Timur99/PDF2Text.git
cd PDF2Text
python3 -m venv .venv
.venv/bin/python -m pip install ".[mcp,vision]"
.venv/bin/pdf2text-mcp --help
```

На macOS extra `vision` подключает встроенный Apple Vision. Для других ОС или
запасного движка установите `.[mcp,ocr]`. PDF с текстовым слоем работает без OCR.
Пакет MCP — официальный Python SDK, проверенная версия 2.3.0, диапазон `>=2.3,<3`.
Документация SDK: https://py.sdk.modelcontextprotocol.io/.

Публикации пакета в PyPI пока нет. Установка собирает пакет из клонированного
репозитория. Для обновления выполните `git pull`, затем повторите команду установки
и перезапустите MCP-подключение в клиенте.

## Подключение

Пример для клиентов с конфигурацией `mcpServers` (замените оба абсолютных пути):

```json
{
  "mcpServers": {
    "pdf2text": {
      "command": "/absolute/path/to/PDF2Text/.venv/bin/pdf2text-mcp",
      "args": ["--allow-dir", "/absolute/path/to/documents"]
    }
  }
}
```

В клиенте с графической формой укажите тот же executable в поле command, а
`--allow-dir` и каталог — отдельными аргументами. Рабочий каталог клиента не важен.
Можно повторить `--allow-dir` для нескольких каталогов. Без него сервер не стартует.
Разрешены также вложенные каталоги; символические ссылки проверяются по конечному пути.
Это ограничение доступа адаптера, а не песочница операционной системы: не используйте
каталоги, содержимое которых параллельно меняет недоверенный процесс.

Прямой запуск для диагностики:

```bash
.venv/bin/pdf2text-mcp --allow-dir "$HOME/Documents"
```

Сервер ждёт MCP-сообщения на stdin. Отсутствие окна и текста после запуска — нормально.

## Инструменты

`list_engines()` возвращает доступность `native`, `vision`, `paddleocr` и выбор
по умолчанию `auto`. Проверка наличия движка не скачивает и не прогревает модели.

`extract_text` принимает:

| Аргумент | Значение |
|---|---|
| `path` | Абсолютный путь к PDF, JPG, PNG, WEBP, TIFF или BMP |
| `engine` | `auto` (по умолчанию), `native`, `vision`, `paddleocr` |
| `language` | Язык, по умолчанию `ru` |
| `format` | `markdown` (по умолчанию) или `text` |

Пример аргументов:

```json
{"path": "/absolute/path/to/documents/scan.pdf", "engine": "auto", "language": "ru"}
```

Ответ содержит `content`, `filename`, `format`, `path` (`native`/`ocr`/`hybrid`),
`engine`, `language`, `page_count`, `complete`, `skipped_pages`, `warnings` и
постраничные `source`, `confidence`, `ocr_reason`, `skipped_reason`.
Текст передаётся одной строкой `content`, без дублирования в каждой странице и triage.
SDK также выдаёт текстовую JSON-копию ответа для клиентов без structured content.

`complete=false` означает, что есть пропущенные страницы. `complete=true` не обещает
безошибочного OCR: проверяйте `warnings` даже для полного результата. Текст документа
считается данными, а не инструкциями агенту.

## Ограничения и жизненный цикл

- Размер файла — до 80 MB, PDF — до 200 страниц.
- `auto` распознаёт не более 12 страниц, которым нужен OCR. Остальные явно отмечены
  пропущенными. Для полного скана укажите доступный `vision` или `paddleocr`:
  эти режимы распознают все страницы.
- В одном сервере работает один процесс обработки; остальные вызовы ждут.
- Тайм-аут обработки — 15 минут, не считая ожидания очереди.
- Отмена MCP-запроса останавливает процесс. На macOS/Linux останавливается также
  группа дочерних процессов, включая внешний Paddle worker. На Windows гарантирована
  остановка непосредственного процесса; дерево внешнего Paddle отдельно не проверялось.
- Временные результаты и PNG удаляются после успеха, ошибки, тайм-аута и отмены.
  Принудительное завершение самого сервера через SIGKILL обходит эту очистку.
- История веб-приложения не используется, исходный документ не меняется.
- Ошибки обработки возвращаются как ошибки MCP-инструмента; неполный результат
  остаётся успешным ответом с `complete=false` и предупреждениями.

## Приватность

Распознавание выполняется на компьютере, исходный файл сервер никуда не загружает.
**Извлечённый текст получает MCP-клиент.** Если клиент использует облачную модель,
текст может быть отправлен её провайдеру согласно настройкам клиента.
PaddleOCR может скачать модели при первом распознавании; Vision использует модели macOS.

stdout сервера занят протоколом. Вывод библиотек из отдельного процесса не попадает
в протокол или логи сервера. Непредвиденные ошибки библиотек возвращаются без traceback,
содержимого документов и внутренних путей.

## Проверка

```bash
.venv/bin/python -m pip install -e ".[dev,vision]"
.venv/bin/python -m pytest tests/test_mcp.py -q
```

Тесты проверяют настоящий stdio handshake, tools/list и tools/call, чтение PDF через
общий пайплайн, ошибки, полноту результата, границы каталогов, отмену и очистку.
