# Дизайн local_OCR

Спецификация интерфейса. Дополняет `ARCHITECTURE.md` (что система делает)
и `PROJECT_PLAN.md` (в каком порядке). Здесь — что видит пользователь.

## Направление

**macOS-native каркас + серифная типографика для распознанного текста.**

Каркас системный, потому что Этап 3 — упаковка в `.dmg` через Tauri. Веб-MVP
и десктоп не должны разъезжаться: системная палитра даёт тёмную тему без
отдельной работы, а сайдбар, toolbar и grouped list — знакомые паттерны.

Распознанный текст набирается **серифом**. Это результат работы продукта,
документ, а не элемент интерфейса. Сериф отделяет «то, что мы достали из файла»
от «того, что мы про это говорим». Всё остальное — системный гротеск.

## Главный принцип

**Triage должен быть виден.** Это единственное, чем продукт отличается от
«загрузить PDF в OCR». Пользователь обязан понимать без объяснений:

- какой путь сработал — native, OCR или hybrid;
- сколько страниц ушло в OCR и **почему**;
- что осталось нетронутым.

Бэкенд уже отдаёт всё для этого. Интерфейс, который показывает только текст
результата, выбрасывает главную ценность продукта.

Второй принцип — **никакой тихой деградации**. Если авто-режим урезал OCR
до лимита, если движок недоступен, если triage не уверен — это видно на
экране, а не только в логах.

| `--danger-fill` | `#ffe9e8` | `#4a1717` | Плашка ошибки |
| `--danger-text` | `#8c0d12` | `#ffb3ae` | Текст ошибки |
| `--ok` | `#147a3d` | `#30d158` | Статус «готово» |

**Правило заливок:** текст на цветной подложке берёт цвет из той же семьи
(`--accent-text` на `--accent-fill`), никогда не чёрный и не серый.

Синий зарезервирован под triage — «эта страница прошла OCR». Он не должен
использоваться декоративно, иначе легенда перестанет читаться. Жёлтый —
предупреждения, красный — ошибки. Эти три цвета не пересекаются по смыслу.

**Почему два синих.** Системный `#007aff` под белым текстом 13px даёт контраст
4,02:1 при норме WCAG AA 4,5:1. Поэтому заливки, поверх которых лежит белый
текст — выбранный ряд сайдбара и кнопка «Новый файл», — берут `--accent-strong`
(5,6:1 в светлой, 4,7:1 в тёмной). `--accent` остаётся для обводок, иконок и
текста-ссылки, где порог другой.

### Типографика

```
--font-ui   -apple-system, BlinkMacSystemFont, "SF Pro Text", "Helvetica Neue", sans-serif
--font-doc  "New York", "Iowan Old Style", Georgia, "Times New Roman", serif
--font-mono ui-monospace, SFMono-Regular, Menlo, monospace
```

| Роль | Размер | Начертание | Семейство |
|---|---|---|---|
| Заголовок документа | 22px / `-0.01em` | 500 | ui |
| Заголовок секции | 15px | 500 | ui |
| Тело интерфейса | 13px | 400 | ui |
| Метаданные, подписи | 12px | 400 | ui |
| Легенда, сноски | 11px | 400 | ui |
| **Распознанный текст** | **15px / 1.7** | **400** | **doc** |
| Номера страниц, confidence | 11px | 400 | mono |

Два начертания: 400 и 500. Никаких 600/700 — на системном фоне читаются тяжело.

Регистр предложения везде. Никаких ВЕРХНИХ РЕГИСТРОВ и Заголовков С Больших Букв.

### Размеры

Отступы: `4 · 8 · 12 · 16 · 20 · 24 · 32`.

Радиусы: `5px` мелкие контролы · `6px` ячейка страницы · `7px` сегментированный
контрол · `10px` grouped-карточка · `11px` окно.

Границы — `0.5px` (волосяная линия macOS), `1px` только там, где 0.5 не
отрисовывается.

Ширина сайдбара — `186px`, фиксированная. Колонка контента — не шире `720px`
по тексту, чтобы строка распознанного текста оставалась читаемой.

## Каркас

```text
┌─────────────────────────────────────────────────────────────┐
│ toolbar: имя файла │ режим (сегменты) │ язык │ действия      │
├──────────────┬──────────────────────────────────────────────┤
│ sidebar      │ content                                       │
│              │                                               │
│ Сегодня      │  Заголовок файла                              │
│  · документ  │  метаданные строкой                           │
│  · документ  │                                               │
│ Вчера        │  ┌ grouped list: факты triage ─────────────┐  │
│  · документ  │  └──────────────────────────────────────────┘ │
│              │  полоска страниц + легенда                    │
│              │  плашки предупреждений                        │
│              │  ───────────────────────────────              │
│              │  распознанный текст (сериф)                    │
└──────────────┴──────────────────────────────────────────────┘
```

Сайдбар — история задач из `GET /api/v1/jobs`, сгруппированная по дням
(Сегодня / Вчера / Ранее) по `created_at`. Ряд: иконка типа (документ или
изображение), имя файла, точка статуса. Выбранный ряд — заливка
`--accent-strong`, белый текст.

История живёт только пока запущен процесс: `JobStore` держит задачи в памяти
(`backend/infra/storage.py:25`), `job.json` пишется на диск, но при старте не
читается. После перезапуска сайдбар пуст, а каталоги в `data/jobs/` остаются
сиротами. Чинится в Э1.5 (персистентность jobs), интерфейс менять не придётся —
источник тот же эндпоинт.

## Компоненты

### Сегментированный контрол — выбор режима

Строится из `GET /api/v1/engines`. Пока движков три (`auto`, `native`,
`paddleocr`) — сегменты. **На Этапе 4 добавится MinerU: четыре пункта —
предел для сегментов, дальше контрол меняется на popup button.** Разметка и
обработчики должны это пережить — источник данных один и тот же эндпоинт,
меняется только отрисовка.

Недоступный движок (`available: false`) не выключается. Он кликается и в ответ
показывает причину и команду установки. Выключенный контрол не объясняет себя.

### Grouped list — факты triage

Карточка `--bg-grouped`, радиус 10px, ряды по 9px вертикали, разделители
`0.5px` с отступом слева 14px. Слева — подпись `--label-3`, справа — значение
`--label`. Ключевая строка «Страниц через OCR» выделена плашкой
`--accent-fill` / `--accent-text`.

Состав рядов зависит от того, что реально пришло:

| Ряд | Источник | Когда показывать |
|---|---|---|
| Тип документа | `triage.pdf_type` | PDF |
| Уверенность triage | `triage.confidence` | PDF, если < 0.9 |
| Путь обработки | `result.path` | всегда |
| Движок | `result.engine` | всегда |
| Страниц через OCR | `metadata.ocr_pages` / `page_count` | всегда |
| Время triage | `triage.processing_time_ms` | PDF |

Ряд не рисуется, если данных нет. Пустых значений и прочерков быть не должно.

### Полоска страниц

Ряд ячеек по числу страниц, каждая 30px высотой, радиус 6px, номер моноширинным
11px. Native — `--bg-grouped` / `--label-3`. OCR — `--accent-fill` /
`--accent-text`. Под полоской легенда 11px `--label-4`.

Ячейка кликается: показывает текст только этой страницы. Повторный клик или
«Все страницы» возвращает полный результат. Для OCR-страницы дополнительно
выводится `confidence` моноширинным.

Полоска — CSS-грид `repeat(auto-fill, minmax(32px, 1fr))`, а не flex: ряды
обязаны совпадать по ширине ячеек, иначе последний ряд растягивается и карта
перестаёт читаться как карта. При числе страниц больше 120 ячейки сжимаются
до 18px и номера скрываются — остаётся только цветовая карта.

### Плашки

Предупреждение — `--warn-fill` / `--warn-text`, радиус 10px, иконка слева.
Источник: `result.warnings`. Показываются **все**, каждое отдельной строкой.

Критично: авто-режим ограничивает OCR двенадцатью страницами
(`MAX_AUTO_OCR_PAGES` в `backend/app/pipeline.py`) и дописывает предупреждение
в `warnings`. Без этой плашки пользователь молча получит неполный результат.
Плашка обязана быть выше текста результата, а не под ним.

Ошибка — `--danger-fill` / `--danger-text`, тот же формат. Источник: `job.error`.

### Распознанный текст

Сериф 15px, `line-height 1.7`, ширина не больше 720px.

Результат приходит как Markdown, и показывать его сырым нельзя: пользователь
видит `## Deep` вместо заголовка, и сериф теряет смысл. Markdown разбирается
в DOM: заголовки `#`–`####`, списки, цитаты, разделители, `**` / `*` / обратные
кавычки внутри строки. Заголовки набираются **гротеском** — это структура
документа, а не его голос; тело остаётся серифным.

**Только `createElement` и `createTextNode`, никогда `innerHTML`.** Содержимое
приходит из пользовательского документа и не является доверенным — это
требование `ARCHITECTURE.md` («HTML/Markdown очищаются перед отображением»).
Разбор Markdown не исключение: он строит узлы, а не склеивает строку разметки.
То же касается имени файла и текстов ошибок.

Кнопка «Копировать» отдаёт исходный Markdown, а не `textContent` отрисованного
DOM — иначе из буфера пропадёт вся разметка.

## Состояния задачи

`JobStatus` объявляет восемь значений, пайплайн использует шесть.

| Статус | Что на экране |
|---|---|
| `queued` | Прогресс 1%, «Файл принят, обработка в фоне» |
| `preparing` | Прогресс 5%, «Проверка файла» |
| `triaging` | Прогресс 15%, «Классификация PDF» |
| `running` | Прогресс 30–80%, «OCR 3/12: стр. 7» — счётчик страниц |
| `postprocessing` | Прогресс 85%, «Сборка результата» |
| `completed` | Полный экран результата |
| `failed` | Плашка ошибки, действия остаются доступны |
| `cancelled` | **Не отрисовывается.** Эндпоинта отмены нет |

Прогресс-бар — 4px, `--accent`, на подложке `--separator`. Под ним строка
`job.message` 12px `--label-3`.

Опрос — `GET /api/v1/jobs/{id}` каждые 400мс. WebSocket из `ARCHITECTURE.md`
пока не реализован; когда появится `WS /api/v1/jobs/{id}/events`, меняется
только транспорт, состояния те же.

### Пустое состояние

Центрированная зона: иконка, «Перетащите PDF или изображение», кнопка
«Выбрать файл», сноска «Файлы не покидают компьютер». Вся площадь контента —
приёмник drop, не только видимый прямоугольник. При перетаскивании — рамка
`--accent`, пунктир 2px.

## Ошибки

Тексты приходят из `pipeline.py` готовыми и уже объясняют, что делать. Задача
интерфейса — не переписывать их, а показать и дать действие.

| Ситуация | Действие рядом с плашкой |
|---|---|
| PaddleOCR не установлен | Команда `pip install '.[ocr]'` моноширинным, с копированием |
| Документ требует OCR в режиме Native | Кнопка «Повторить в режиме Авто» |
| Изображение в режиме Native | Кнопка «Повторить в режиме Авто» |
| Слишком много страниц | Показать лимит и число страниц |
| Файл больше лимита, неверный тип | Плашка без действия |

## Иконка приложения

Страница с четырьмя строками, третья — синяя. Та же мысль, что и вся полоска
страниц в интерфейсе: документ читается напрямую, и только отдельные строки
уходят в OCR. Иконка и продукт говорят одно и то же.

Корпус тёмный (`#39424f`), страница белая, строки серые, одна — `#0060df`.
Тёмный корпус не из вкуса, а из необходимости: первая версия со светлой
заливкой `#e6ebf2` теряла силуэт на белых обоях уже на 32 px. Синий остаётся
единственным цветным элементом — то же правило, что и в интерфейсе.

Генерация — `desktop/make_icon.py`, сборка `.icns` — `iconutil`. Каждый размер
рисуется отдельно со сверхсэмплингом ×4: при уменьшении из одного мастера
1024px строки на 16 и 32 px схлопываются в пятно. На размерах меньше 128 px
строк три вместо четырёх — четыре не разделяются.

Скругление — приближение сетки macOS (тело 824/1024, радиус 185/1024), а не
точная «непрерывная» кривая Apple. Для неподписанной сборки этого достаточно;
перед публикацией стоит прогнать через шаблон Apple.

## Расширение

- Пятый движок — сегменты меняются на popup, остальное не трогается.
- Этап 2 добавляет разворот страницы: полоска остаётся навигацией, под ней
  появляется область просмотра.
- Этап 5 добавляет сравнение — вторая колонка контента с тем же набором
  компонентов, grouped list дублируется для каждого прогона.
- Tauri не меняет ничего: тот же UI, тот же `127.0.0.1`.
